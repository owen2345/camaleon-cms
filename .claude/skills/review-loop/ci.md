# The ci check

The fifth check is **ci**: the GitHub workflow runs of a commit, the rows of `gh run list --commit <sha>`. Setup reads them for the `setup HEAD` (`setup.md`), and a stop that pushes for the pushed commit (`stop.md`). Each read ends with the line `ci <sha> <ok, n/a, no jobs, pending, cancelled or the failed job>` in the ledger, with the `setup HEAD` or the pushed commit as its `<sha>`. The ci field of a PASS line is the value of the last `ci` line of the run for its `<after>`, else n/a.

- The suite runs are the runs of the suite workflows of the table (`procedure.md`, Checks), the workflows that `.github/workflows/release.yml` requires in camaleon-cms. The jobs of the suite runs are the suite jobs. Every other workflow is advisory: a failed suite job fails ci, an advisory run never. An advisory workflow whose newest run completed without `success` or `skipped` adds a note after the value of the `ci` line: `# advisory <workflow> <conclusion>`. The read prints the note (below), and the STOP report repeats it. `<suite>` is one argument: the names of the suite workflows of the table, joined with `|`, for example `'Audit|Test supported versions'` for camaleon-cms.
- ci is n/a when the repo has no workflow file, and after a push when the pushed head carries a skip marker. A head is marked when `<scripts>/head-marked.sh <checkout> <sha>` exits with 0. Its message then holds a bracket marker of `docs/ai/workflows.md` Phase 3, or ends with a `skip-checks: true` trailer after two empty lines. A `skip-checks` line anywhere else in the message does not mark it.
- The commands take the full SHA of the head as `<sha>`: `gh` matches no short SHA. For a marked `setup HEAD`, they take the head of the newest suite run of the branch (`setup.md`, CI).
- Read the suite runs as a background task: `<scripts>/ci-status.sh <project> <sha> <suite>` (`docs/ai/testing.md` "Long commands"). It polls until every suite workflow has a run and every suite run is completed. Then it prints one line per suite workflow: its name, and the id, the attempt and the conclusion of its newest run. After them come the advisory notes (above). The exit code is its result:
  - 0: the lines are the suite runs to read (below) and the advisory notes.
  - 3: a suite workflow still has no run after five minutes, so ci is `no jobs`.
  - 4: a suite run is still pending after an hour, so ci is `pending`.
  - 5: three calls of `gh` one after the other failed, and the read has no result.
- A conclusion `success` or `skipped` passes. For any other conclusion of a suite run, `<scripts>/ci-jobs.sh <project> <run id>` names the jobs that did not pass, with the count of their failed steps.
- A job with a failed step is a failed job, which setup traces (`trace.md`). Any other job that did not pass, or a suite run with no job, did not run to its end. It gets the one rerun of its run (below).
- Rerun a run once. Append `rerun <run id> <attempt>` to the ledger, with the `attempt` of the run on its line of the read. Then run `gh run rerun <run id> --repo <project> --failed`, or the whole run (`gh run rerun <run id> --repo <project>`) when GitHub refuses that. After an accepted rerun, `gh run view <run id> --repo <project> --json attempt --jq .attempt` prints a number above the one on the line. Then read ci again. This sequence stays rule text until a follow-up PR gives it a script (intended).
- A workflow run with a `rerun` line anywhere in the ledger (`grep -a '^rerun ' <ledger>`) gets no second rerun, also from a later run of the loop. The jobs of a workflow run with a `rerun` line are the jobs of its rerun. The line counts as a rerun only when the run shows an `attempt` above the number on the line (the read and the view above). At that number the rerun command never ran or failed: run it now as the one rerun.
- A rerun whose jobs pass gives ci ok. In the rerun of the run of the `setup HEAD`, a job whose failure the trace fixed does not count (`setup.md`, CI). A job of the rerun that does not run to its end, or a refused whole-run rerun, gives ci `cancelled`. Report the run.
