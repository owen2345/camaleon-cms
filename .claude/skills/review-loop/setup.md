# Setup of a run

The first pass of a run follows this file before `procedure.md`, after `SKILL.md` made the copies. Setup resolves the target, reads the PR, makes the ledger ready, appends the run header and reads the ci check of the PR head. A stop before the run header says so in a `PASS 0/8` line (`procedure.md`, PASS line).

- **Target:** the real path of the checkout (`git -C ../<repo> rev-parse --show-toplevel`) and its GitHub project (`gh repo view --json nameWithOwner --jq .nameWithOwner`, in the checkout). `<project>` must be the repository of `origin` too: `gh repo view "$(git -C <checkout> remote get-url origin)" --json nameWithOwner --jq .nameWithOwner` prints it, else stop.
- **PR:** `gh pr view <pr> --repo <project> --json state,headRefName,baseRefName,headRefOid,headRepository` gives its state, its branches, its head commit and its head repository. `gh pr view <pr> --repo <project> --json body --template '{{.body}}' > tmp/review-loop/<repo>/<pr>.description.md` saves its description, which Verdicts step 3 of `procedure.md` reads. Stop unless `<head>` and `<base>` match `^[A-Za-z0-9_][A-Za-z0-9._/-]*$`: the commands below use both names without quotes. Then fetch both branches: `git -C <checkout> fetch origin <head> <base>`. The run continues only when each condition below holds:
  - The PR is open, and its `headRepository.nameWithOwner` is `<project>`, the repository of `origin`, where the STOP push goes.
  - `origin/<head>` is at the head commit of the PR, and the checkout is on the head branch at `origin/<head>`.
  - The checkout is clean: `git -C <checkout> status --porcelain` prints nothing.
  - The tests of the checkout are RSpec specs (`git -C <checkout> ls-files 'test/*_test.rb'` prints nothing), and it has `bin/rubocop` and `bin/rspec`.

  Every range to the base below starts at `<base-ref>`: `origin/<base>`, never the local base branch, which can lag behind.

  When `git -C <checkout> diff --name-only <base-ref>...HEAD -- openspec/` prints a path, run the `openspec validate` commands of `AGENTS.md` once, in the checkout, and stop on a failure.
- **Ledger:** `tmp/review-loop/<repo>/<pr>.md` in camaleon-cms, whatever the target repo, never committed. Create it when it has no `## Run` header, seeded as pass 0 from the PR's memory entry, if any. The seed holds the rows that every STOP adds there (`procedure.md`, Pass states and stop). It also holds any other refuted entry as REFUTED, and any skipped entry as DECISION, or as FIXED when a later commit fixed it. Each run appends, in one command, `## Run <date>, effort <level>` and `setup HEAD <sha> | <checkout> | <project> | <head> | <base-ref> | <polished>`, with the PR head that setup found. It counts its passes from 1, and the rows of earlier runs still count for the verdict checks.
  - `<polished>` is the `<after>` of the newest PASS line of a pass whose review ran: the text that an earlier run polished. `LC_ALL=C awk '/^PASS [1-8]\// && !s[$0]++ {if (r) p = $0; r = 0} /^review$/ {r = 1} END {print p}' <ledger>` prints that line, before the append. A `review` line (`procedure.md`, Ledger rows) marks a pass whose review ran, and a PASS line that a STOP quotes counts once. A `PASS 0/8` line is not one, nor the PASS line of a pass that stopped before its review: neither polished any text. The fix commits of a pass whose review ran count as polished, also when no later review read them. It is `none` when the ledger has no such line, or when the repository lacks that commit (`git -C <checkout> rev-parse -q --verify '<after>^{commit}'` exits with 1).
- **CI:** read the ci check of the `setup HEAD` as `ci.md` says. The poll is a background task (its `task` line) that runs during the review. Append the `ci` line when the read ends, with the `setup HEAD` as its `<sha>`. Before its PASS line, pass 1 waits for a poll that still runs (`docs/ai/testing.md` "Long commands").

  Test the `setup HEAD` for a skip marker as `ci.md` says: a marked head has no suite run of its own. The `<sha>` of the ci commands is then the head of the newest suite run of the branch: `S='Audit|Test supported versions' gh run list --repo <project> --branch <head> --limit 100 --json headSha,workflowName --jq '[.[] | select(.workflowName | test("^(" + env.S + ")$"))] | .[0].headSha // empty'`. The command prints nothing when the branch has no suite run (ci n/a), and a failed `gh` is no result. That run gives the ci result of HEAD only when no code changed since its commit. When `git -C <checkout> rev-parse -q --verify '<sha>^{commit}' > /dev/null` exits with 1, or `git -C <checkout> diff --name-only <sha> HEAD` lists a code file (`AGENTS.md` "Verify before pushing"), ci is n/a.

  Trace a failed suite job of that read (`trace.md`) in pass 1. Trace it before the review when possible, else before the PASS line. Trace it before the rerun of its run, which the trace can start. A job whose failure the trace fixed fails again there, and that failure does not count. The read ends before the trace of a failed job, else after the one rerun of a run, when it gets one. The run stops on `no jobs`, `pending` or `cancelled` (`ci.md`), at the end of pass 1, which commits its fixes first.
